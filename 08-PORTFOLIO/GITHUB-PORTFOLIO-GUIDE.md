# GITHUB PORTFOLIO GUIDE

## Repository concept

Suggested repository:
`omari-technologies-iam-career-lab`

## Never commit

- passwords
- API keys
- access tokens
- MFA recovery codes
- private certificates
- real customer data
- personal identifiers
- proprietary company data
- VM disk images unless intentionally licensed and appropriate

## Recommended repository structure

```text
omari-technologies-iam-career-lab/
├── README.md
├── year-1-help-desk/
├── year-2-iam-analyst/
├── year-3-iam-engineer/
├── year-4-iam-architect/
├── scripts/
├── architecture/
├── evidence/
└── docs/
```

## Each project README

Include:
- business scenario
- problem
- architecture
- tools
- implementation
- screenshots
- troubleshooting
- security controls
- validation
- lessons learned
- what would change in production

## Employer-facing language

Describe outcomes, not just commands:
"Designed and operated a domain-based Windows lab implementing AD DS, DNS, GPO, RBAC concepts, lifecycle workflows and IAM automation."

Do not claim production experience from a lab. Label it as a hands-on project/lab.
